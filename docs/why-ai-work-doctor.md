# 为什么是 ai工作医生（优势与边界全说明）

> 这份文档回答三个问题：**它解决什么问题**、**凭什么是它**、**它做不到什么**。
> README 只放结论，这里放论证和证据。

---

## 1. 问题：桌面端 agent 的四种固定失效模式

长会话里，agent 的失败方式高度可预测（不是"能力不够"，是"没有刹车"）：

| 失效模式 | 现场长什么样 | 代价 |
|---|---|---|
| **重复读取 / 重复搜索** | 同一个文件整篇读第 4 遍；同一个 `grep` 换个引号再跑 | 上下文被垃圾占满，token 烧光 |
| **无产出空转** | 连续好几轮"我再试一次"，没有任何新信息 | 无人值守时能烧几小时 |
| **假成功** | "已部署 ✅" / "编译通过" / "端口在听"，但功能就是坏的 | 你信了，事故后置到线上 |
| **不可逆损失** | `rm -rf`、覆盖用户文件、`taskkill /IM node.exe`、`push --force` | 桌面端直接动**你的真实机器**，云沙箱没有这一层风险 |

前三种是"循环"，第四种是"破坏"——**大多数 skill 只治前三种，桌面端最贵的恰恰是第四种。**

## 2. 为什么"提醒式 prompt"救不了

1. **弱模型直接忽略**："请勿重复读取"是愿望，不是约束。没有数字上限，模型无法判断"到没到线"。
2. **强模型也会漂移**：长上下文里规则会被稀释，越到后面越像背景噪音。
3. **不可验收**："要谨慎""注意安全"这类句子，你事后无法判断它到底遵守了没有。
4. **每次都要手动贴**：贴一次只在当前对话有效，换个宿主、换个项目就没了。

**所以本插件的设计前提是：规则必须能被机器执行、被用户一眼验收。**

## 3. 我们做对了什么（设计原则）

| 原则 | 落地方式 |
|---|---|
| **每条规则三要素齐全** | `触发条件` + `具体动作` + `数字上限`。写不出数字上限的句子一律不进（写进 [CONTRIBUTING.md](../CONTRIBUTING.md) 当硬门槛） |
| **可验收** | 固定回执串：`LOOP at N:`、`BUDGET: <动作> xN → 换 <新方法>`、`BLOCKED: 需要 X`、`CHECKPOINT:`、`HANDOFF`。你在对话里**看得见**它熔断了 |
| **常驻部分极短** | 会被注入全局指令、**每轮对话都在上下文里**的东西只有 20 行（约 4 KB）。细节走三层渐进披露 |
| **三层结构，按需加载** | 常驻卡（20 行）→ SKILL.md 正文（201 行，含反例与判定）→ `references/desktop-cn.md`（121 行命令级坑位表，命中症状才读） |
| **不可逆操作两阶段** | 打印 `IMPACT: <命令> 将不可逆影响 <目标>（备份：<路径>）` → **等用户明确确认** → 才执行。沉默不算确认 |
| **先备份后写** | 改前 `Copy-Item $p "$p.bak-<时间戳>"` 或 `git stash/commit`；改前改后各取一次哈希，哈希没变说明改错了文件 |
| **只杀自家进程** | kill 前核对 PID + 命令行；禁止 `taskkill /IM`、`pkill -f`、`killall` |
| **无人值守设墙** | 用户离开前先声明预算（≤N 次调用 / ≤M 分钟），每 10 步或 10 分钟写 `CHECKPOINT`，到点必须停并交 `HANDOFF` |

18 条规则的分工（R0 输入闸门 + R1–R17）（详见 [SKILL.md](../SKILL.md)）：

- 治**无目标乱动**：**R0 输入闸门**（消息里没有「对象+动作」→ 零工具调用，先问一句；专治"发个『在』就全盘扫 1 分 53 秒"）
- 治**循环**：R1 环境只探一次、R2 一次建图（含**命令成本上限**：限目录/限深度/20 秒超时/禁盘符根递归）、R3 一读多动、R4 空转熔断、R6 预算上限（次数 + 单条命令 20 秒）
- 治**假成功**：R5 行为级验收（按改动类型给证据：UI/接口/逻辑/配置/文档）
- 治**破坏**：R7 进程端口收口、R8 只杀自家进程、R10 先备份后写、R11 不可逆两阶段闸门、R12 密钥不落盘
- 治**挂死与烧钱**：R9 非交互执行、R13 无人值守设墙
- 治**中文环境**：R14 + `references/desktop-cn.md`（含"某软件装在哪"的 5 秒级定位法）

## 4. 逐条对比

| 维度 | 裸 agent | 提醒式 prompt | 云端沙箱 agent | **ai工作医生** |
|---|---|---|---|---|
| 规则强度 | 无 | 建议 | 依赖沙箱能力 | **硬规则 + 数字上限 + 固定回执** |
| 生效范围 | — | 当前对话 | — | **该宿主以后所有对话、所有项目** |
| 模型无关性 | — | 弱模型忽略 | — | **纯文本上下文，任何模型都吃** |
| 宿主覆盖 | — | 手动逐家贴 | — | **20 个桌面端 agent（国产 8 家）+ 18 个项目级注入点** |
| 重复读取 | 无上限 | 靠自觉 | 部分缓解 | **2 次封顶，第 3 次必须换方法** |
| 完成判定 | 它自己说了算 | 靠自觉 | 沙箱可观测 | **必须有运行时证据，否则交回用户** |
| 破坏性操作 | 直接干 | 无强制力 | 沙箱隔离 | **备份 + `IMPACT:` 闸门 + 等确认** |
| 进程/端口残留 | 常见 | — | 环境销毁即消失 | **记 PID/端口，收工前验证释放** |
| 中文 Windows | 无限试错 | — | 不涉及 | **环境探测一次 + 编码兜底 + 121 行坑位表** |
| 安装成本 | — | 每次复制粘贴 | — | **一条命令 / 双击** |
| 可撤销 | — | — | — | **`-Uninstall` 精确删除，用户原文逐字不动** |
| 依赖与权限 | — | — | 需要平台 | **0 依赖、不联网、不需要管理员** |

## 5. 20 个宿主，且每个路径都有出处

**这是本插件最容易被低估的优势**：网上的"配置文件"大多是抄来的，路径一旦过时就会**静默失效**——
用户以为装上了，其实宿主根本没读。我们的规则是：**官方文档/源码查得到的才写，查不到的不猜**，
查不到的一律改成"手动粘贴"并在文档里写清楚。

| 阵营 | 覆盖 | 注入位置（示例） | 证据 |
|---|---|---|---|
| 字节 | Trae、Trae CN、Trae CLI | `~/.trae/user_rules/…`、`.trae/rules/*.md`、`~/.trae/skills/` | docs.trae.ai / docs.trae.cn |
| 腾讯 | CodeBuddy（IDE + CLI） | `~/.codebuddy/CODEBUDDY.md`、`.codebuddy/rules/<name>/RULE.mdc` | codebuddy.cn/docs |
| 百度 | 文心快码 Comate | `.comate/rules/*.mdr`（**必须是 `.mdr`**） | cloud.baidu.com/doc/COMATE |
| 阿里 | Qoder、Qoder CN（IDE 与 CLI 两套体系） | `.lingma/rules/*.md`（IDE）、`~/.qoder/AGENTS.md`、`.qoder/rules/*.md`（CLI） | docs.qoder.com / docs.qoder.cn |
| 月之暗面 | Kimi Code CLI | `~/.kimi/skills/`（也读 `~/.agents/skills/`） | kimi-cli 官方仓库 |
| 其它 | Codex、Claude Code、Cursor、Cline、Roo、Continue、OpenHands、DSH/CC GUI、Gemini CLI、Qwen Code、Zed、Copilot、iFlow | 见 [INSTALL.md](../INSTALL.md) | 逐条附链接 |

顺带治了几个"同一家族两套体系"的坑：Qoder CN IDE 用 `.lingma/rules`、Qoder CLI 用 `.qoder/rules`；
CodeBuddy IDE 是"每规则一个目录 + `RULE.mdc`"、CLI 才是 `rules/*.md` 平铺；Comate 只认 `.mdr`；
Cursor 只认 `.mdc`（同目录 `.md` 会被忽略）。**结构写错 = 静默不生效**，这些我们都写对了。

## 6. 中文用户的坑，替你踩完了

`references/desktop-cn.md`（命中症状才读）覆盖：

- **编码**：GBK/936 乱码、`UnicodeEncodeError`、PS 5.1 的 `Out-File -Encoding utf8` 写 BOM 会毁掉 JSON/frontmatter、
  含中文的 `.ps1` 必须存 UTF-8 with BOM、GBK 老文件别"顺手统一成 UTF-8"
- **中文关键词搜索**：**GNU grep 不做转码**——用 UTF-8 的中文 pattern 搜 GBK 文件是**静默 0 命中**，不是报错；
  正确姿势是首搜就带编码（`Select-String -Encoding Default` / `rg --encoding gbk`），0 命中 = 换词或问入口，不是"不存在"
- **路径**：中文/空格路径、超长路径 `ENAMETOOLONG`、`C:\Users\中文名` 下工具链炸、OneDrive 重定向导致文件锁与监听失效
- **Shell 差异**：Windows 上 `rg/grep/sed/awk/head/wc` **默认都不存在**（只有 `findstr`）；`curl` 是 `Invoke-WebRequest` 别名；
  `mkdir -p` 不存在；PS 5.1 没有 `&&`；Git for Windows 默认 `core.autocrlf=true` 会让 `.sh` 报 `bad interpreter: /bin/bash^M`
- **进程/端口**：端口占用判定、dev server 后台化 + 日志轮询、文件被占用时**不要反复重试**
- **网络**：npm/pip 镜像、raw.githubusercontent 拉不动时的换源纪律（**同一 URL 最多 2 次，第 3 次必须换源**）
- **假成功**：改了源码但页面没变（改的是 `dist/` 不是源码）、HMR 失效、缓存
- **挂死的交互式命令**：`npm create`、无 `-m` 的 `git commit`、`git rebase -i`、`ssh` 输密码、`npm login`、`docker exec -it`
- **多 agent 并发写同一工作区**、无人值守预算、真实文件上的危险操作

## 7. 工程质量（可验证，不是自我评价）

| 项 | 做法 | 验证方式 |
|---|---|---|
| 幂等 | 标记块写入；内容一致直接报"已是最新" | 连装两次，`Get-FileHash` 相同 |
| 可预览 | `-DryRun` / `-n` 打印将写入的路径与字符数 | 预览后检查文件未变 |
| 可撤销 | `-Uninstall` 只删标记块；"只剩我们内容"的文件整份删除 | 装→卸，用户原文逐字还原 |
| 不破坏编码 | UTF-8 无 BOM / UTF-8 BOM / GBK **按原编码读写** | GBK 文件卸载后仍是 GBK 字节 |
| 不越界 | 只写"检测到"的宿主；`-Root` 沙箱下 `%APPDATA%`、`Documents` 都不跑出沙箱 | 未检测到的宿主不建目录 |
| 按需安装 | `-Select` 菜单 / `-Only` 点名 / 双击 `activate.cmd` | 菜单显示"是否已安装 + 将写哪个文件" |
| CI 校验 | frontmatter 合法、`name` 正则、常驻卡行数、编码、脚本语法、全局+项目级自测（幂等/还原/不越界） | `.github/workflows/validate.yml` |
| 无依赖 | 只用 PowerShell 5.1 / bash 内建能力；不联网、不改注册表、不要管理员 | 通读 `install.ps1`（约 30 KB，含注释） |

**开发过程也是证据**：v2.0 由 5 个独立专家视角评审（中文 Windows 环境实测、宿主注入机制、规则工程、
开源发布、事故复盘）后收敛；v2.1 派了 4 个调研子智能体逐个核对国产 agent 的官方文档，
把每条路径的出处写进 INSTALL.md。**凡"查不到"的一律不写文件**。

## 8. 已知边界（做不到的，写清楚）

1. **规则只在"会读文件"的宿主里生效**。把规则存在 UI / 账号 / 云端的宿主（Cursor 的 User Rules 官方明确
   "不存在磁盘文件"、Windsurf 全局规则、智谱 CodeGeeX、部分企业版云端规则）无法从文件系统注入——我们只给一段可粘贴的文字。
2. **它是指令层，不是沙箱**。真正的权限控制、命令拦截钩子、文件事务与回滚、凭据保险库、token 计费熔断、
   多 agent 会话锁属于**宿主**职责。宿主没这些能力时，本插件只能用规则 + 回执把风险和你可见性补上。
3. **不保证模型一定遵守**。硬规则显著提高遵守率（有数字、有回执、可被用户当场质询），但任何 prompt 层方案
   都不是强制的。要 100% 拦截，得在宿主层做钩子。
4. **不做代码质量**。它不管你的架构、命名、测试覆盖率——只管"别空转、别假成功、别搞坏机器"。
5. **路径会随宿主版本变**。我们核对的是当前官方文档；宿主改了路径，欢迎提 issue（[SECURITY.md](../SECURITY.md)
   里把"未经验证的宿主路径"明确列为缺陷）。

## 9. 谁该用

- ✅ 你在中国用 Windows，跑 Codex CLI / Claude Code / Cursor / Trae / CodeBuddy / 通义灵码(Qoder) / Kimi 等桌面端 agent
- ✅ 你被"改一个 bug 烧掉半天额度""它说部署好了其实没好""它把你没提交的文件删了"坑过
- ✅ 你希望装一次就不用再管，且随时能干净卸掉
- ❌ 你只在网页版聊天框里问问题（没有本地文件/进程可管，收益有限）
- ❌ 你想要的是代码审查、架构建议、测试生成（那是另一类工具）

## 10. 一分钟上手

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -List      # 认出本机装了哪些
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Select    # 挑要装的（或双击 activate.cmd）
```

验证：**新开一个对话**，问「说出 ai工作医生 的预算上限」→ `read 2 / search 2 / deploy 2 / no-op 2 / tool-err 3`。

撤销：`.\install.ps1 -Uninstall`（全局）/ `.\install.ps1 -Project <目录> -Uninstall`（项目级）。
