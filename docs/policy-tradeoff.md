# 两条政策：成本闸门 与 防污染

插件的能力提升分两种：**改规则**（提高成功率）和**加规则**（有成本）。
这两条政策决定"什么时候允许改"，避免越用越臃肿、越用越互相干扰。

## 一、成本闸门：成功率优先，但不能拿 token 换歪

阈值写在 [`eval/budget.json`](../eval/budget.json)，由 `card-audit.ps1` 机械执行（超了 CI 直接红）：

| 限制 | 阈值 | 为什么 |
|---|---|---|
| 卡长 | ≤ 1760 字符 ≈ **1100 tokens** | 当前 1690 字符 ≈ 1056 tokens，只剩 ~70 字符余量 |
| 规则条数 | ≤ **12 条** | v2.4 的 2229-token / 18 条卡实测让模型变笨 |
| 单次发版卡长增幅 | ≤ **60 字符** | 防止一次改动吃光余量 |
| 证据门槛 | **≥ 2 个会话**命中同类失败 | 1 次事故记事故，不改卡 |
| 采样窗口 | 最近 **14 天** | 不复现的失败模式，规则该撤 |

**判定公式（人判，不靠感觉）**：

```
净收益 = (被修复的失败次数 × 单次平均浪费秒数或错误次数) − (新增 tokens × 每周会话数 × 单价)
```

若净收益为正但**增幅 > 60 字符**，必须合并或删掉一条旧规则——**不允许第 13 条**。

## 二、防污染：多会话长期使用不互相串味

蒸馏的原料是"历史失败"，风险是"把一次性教训写成永久规则"。五道闸：

1. **作用域隔离**：只有跨任务的通用不变式能进卡；任务型经验进 `references/task-*.md`，按需加载，不影响别的任务型。
2. **时间衰减**：默认只采 14 天；老的失败模式不复现就撤规则，而不是留着当护身符。
3. **卡版本对齐**：提案必须区分「新卡仍命中」与「旧卡考古」；后者不能作为改卡依据。
4. **不自动入库**：`distill.ps1` 只产出提案，永不自动改 SKILL.md；入库必须人批 + 探针回归 + 同批会话复跑。
5. **单条可回滚**：一条规则一个 commit，出事 `git revert` 单条，不连坐。

## 三、这两条政策怎么被验证

- `card-audit.ps1`：结构 + 19 条语义条款 + 预算闸门（字符/条数）
- `distill.ps1` 提案末尾自带「成本闸门」与「防污染」两张表，改卡前必须逐条对照
- 每次发版：同批会话复跑，失败数不降就回滚
