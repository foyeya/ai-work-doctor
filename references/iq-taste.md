## 2. 建议进常驻卡的行（1 行，逐字可粘贴）
放在第 14 条之后、`<!-- AIW_CORE:END -->` 之前的同一段列表里：
```markdown
15. **交付即成品**：结论或代码在第 1 行，首行不出现「好的/当然/作为一名 AI」，末段不出现「希望这对你有帮助/综上所述/总之/我们会继续努力」；装饰性 emoji 0 个、加粗每段 ≤1 处、日期统一 `YYYY-MM-DD`；写码前读同目录邻居 ≤2 个并对齐命名与注释语言，重构类改动 `git diff --numstat` 净增行数 ≤0。
```
回执（追加进既有「固定回执」那一行，**不占新行**，只在本次交付含文档或代码时打，≤1 行）：
```text
TASTE: 首行即结论 / 黑名单 0 命中 / 净增 ≤0
```
为什么值这 1 行（三条硬理由，前两条是可验证事实）：
1. **它补的是一条已经存在的窟窿，不是新开范围。** `eval/probes.json` 的 P08「结论先行 + 无 AI 味」与 P09「代码风格与邻居对齐 + 最小 diff」已经占 24 分里的 4 分，`dim` 就叫「审美」，P08 的 `pass` 逐字写着「无「好的/当然/作为一名 AI」开场，无「希望这对你有帮助/总之我们需要注意」式空话收尾，无 emoji 堆砌」。**探针在扣分，规则却一个字没写**——装上插件也拿不到这 4 分。这一行就是把 P08/P09 的判定标准反向写回规则层，让"测试什么"和"要求什么"闭环。
2. **它的失败面没有任何第二道防线。** 代码类问题还有下游兜底：R5 行为级验收、R10 的哈希与改动清单、以及任何一次 code review 都会暴露过度抽象。而"希望这对你有帮助"这类文字垃圾，**R0–R14 里没有任何一条管它，CI 不管，用户的验证清单也不管**——只有这一行能拦。规则的价值 = 失败频率 × 无兜底程度；这一行在"无兜底"上是满分。
3. **它 100% 触发。** 每一次回复本身就是一份交付物，所以这行的生效面和"每轮都在上下文里"的成本完全对齐。
### 为什么不是第 2 候选（纯代码品味行）
我原本的第 2 候选是"先对齐邻居 + 最小 diff + 不造新抽象"。放弃它的理由是它**在同一个行宽里换不出等量的可判定性**：
- 「新增抽象须有 ≥2 处现有先例」需要人来判断"什么算一层抽象"（一个字段算不算？提取常量算不算？），**不是一条 grep 能判定的**，与本次"凡是需要主观判断的一律不进卡片"的要求正面冲突。
- 它的下游兜底已经存在（R5 验收失败会逼着重做、R10 逼着列改动文件与哈希）。
- 所以我把第 2 候选里**唯一机械可查**的两条（读邻居 ≤2 个 / `git diff --numstat` 净增 ≤0）并进第 15 条，剩下的（抽象层级、错误处理不写死分支、不留 TODO、不新增依赖）全部进 `references/iq-taste.md` 按需查。
**如果维护者坚持只保留半句**：砍掉代码后半句（`写码前读同目录邻居…`），保留文本层。理由同上：代码有兜底，文本没有。

## 7. 反例：什么写法反而更 AI 味
这一节本身就是给合成者的护栏，别让"去 AI 味"变成新的 AI 味。
1. **为了"不像 AI"加口语、表情、自嘲**：句尾挂个笑脸表情、开场说"嘿～我来帮你搞定这个"，比"希望这对你有帮助"更像流水线产物，且直接破坏可判定性。
2. **把自查清单当交付物贴出来**：回复末尾列 12 项"已检查"是最典型的自证式啰嗦。所以 §2 的回执写死了"≤1 行、禁止清单"。
3. **机械套用"结论先行"到探索类任务**：诊断还没做完就先给结论 = 编造，与 R5 冲突。R15 的判定是"结果是什么"，不是"必须有结论"。
4. **为压低 `git diff --numstat` 净增行数而删必要代码**：包括错误处理、边界校验，与 R10 / C6 冲突。净增 ≤0 **只对重构类**生效。
5. **为"对齐邻居"而抄邻居的缺陷**：规则是**对齐风格，不对齐缺陷**；邻居有 bug 时照抄等于扩散。
6. **为了满足"前言 0 句"把因果压成电报体**：可读性归零，代价比多一句前言大。
7. **故意写错别字或不规范标点来扮人味**：破坏 D10–D15 的一致性。
8. **在代码里写口语注释**（`// 这里有点 tricky`）：是伪人味，且违反 C5 的"注释讲为什么"。
9. **把 30 条审美规则全塞进常驻卡**：本任务最大的陷阱；`CONTRIBUTING.md` 的反膨胀 5 条就是为拦这个写的。

### 8.3 机械审计脚本（把"可判定"落到可执行）
建议作为 `eval/taste-check.ps1`（只读，不改仓库文件；PowerShell 5.1 兼容）：
```powershell
# 用法: .\taste-check.ps1 -Path .\报告.md [-Refactor]
param([Parameter(Mandatory)][string]$Path, [switch]$Refactor)
# 只判正文散文：剔掉围栏代码块（文档里引用的反例与示例代码不算违规，本文件自测时踩过这个坑）
$raw = Get-Content -LiteralPath $Path -Encoding UTF8
$prose = New-Object System.Collections.Generic.List[string]
$inFence = $false
foreach ($l in $raw) {
  if ($l -match '^```') { $inFence = -not $inFence; continue }
  if (-not $inFence) { $prose.Add($l) }
}
$lines = $prose.ToArray()
# 再剔掉行内代码 span：技术文档里 `2026/5/20`、`SKILL.md` 这类引用是正当内容，不该被判违规。
# 必须逐行处理：若先拼成一整篇再配对，某个未闭合的反引号会跨行吃掉大段内容，制造出假的"中英紧贴"
$t = (($lines | ForEach-Object { $_ -replace '`[^`]*`', '' }) -join "`n")
$fail = 0
function Chk($name, $bad) {
  if ($bad) { "FAIL $name"; $script:fail++ } else { "ok   $name" }
}
# 首行判定从「第一个非空、非标题行」开始：报告一般以 `# 标题` 开头，标题不算前言；
# 末段判定取最后 3 个非空行，避免被空行稀释
$first = ($lines | Where-Object { $_.Trim() -and $_ -notmatch '^\s*#' } | Select-Object -First 1)
$tail  = (($lines | Where-Object { $_.Trim() } | Select-Object -Last 3) -join ' ')
Chk '开场套话'   ($first -match '^(好的|当然|没问题|作为(一名)? ?AI|这是一个很好的问题)')
Chk '空话收尾'   ($tail -match '希望(这|对你)|综上所述|总之|如需.*帮助|我们会继续努力|祝')
Chk '装饰性 emoji' ($t -match '[\uD800-\uDBFF]')
Chk '半角标点'   ($t -match '[\u4e00-\u9fff][,;:!?]')
Chk '日期不统一' ($t -match '\d{4}[/年]\d{1,2}')
$tight = [regex]::Matches($t, '[a-zA-Z0-9][\u4e00-\u9fff]|[\u4e00-\u9fff][a-zA-Z0-9]') |
         ForEach-Object { $_.Value } | Where-Object { $_ -ne 'i工' }   # 品牌名 ai工作医生 写死例外
Chk '中英未加空格' ($tight.Count -gt 0)
$dash = ([regex]::Matches($t, '——')).Count
$cjk  = ([regex]::Matches($t, '[\u4e00-\u9fff]')).Count
Chk '破折号超量'  ($dash -gt [math]::Max(1, [math]::Floor($cjk / 300)))
if ($Refactor) {
  $num = git diff --numstat
  # 每行格式: <新增> <删除> <文件>；制表符分隔
  $add = 0; $del = 0
  foreach ($l in $num) { $c = $l -split "`t"; if ($c[0] -match '^\d+$') { $add += [int]$c[0]; $del += [int]$c[1] } }
  Chk '重构净增为正' ($add -gt $del)
}
"--- $fail 项未通过"
exit ([int]($fail -gt 0))
```
（脚本里的星平面检测靠 `[\uD800-\uDBFF]`，不要写 `\u1F525` 之类——PowerShell 正则的 `\u` 只吃 4 位十六进制，`\u1F525` 会被解析成 `\u1F52` 加字面量 `5`，静默漏检。这是我在本机实测踩到的坑。）
