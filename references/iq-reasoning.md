## 1. 诊断：模型在本维度「显笨」的 6 个可观察行为
每条都写成「**看什么**（客观可观察）+ **为什么现有规则拦不住**」。这些是行为，不是感受。
| # | 可观察行为（判定口径） | 为什么现有 20 行拦不住 |
|---|---|---|
| **D1** | **纯推理空转不被熔断**：连续 ≥3 轮 assistant 消息**没有工具调用、没有新文件/新事实**，每轮都以"接下来我需要确认…"结尾，而每轮的结论其实是同一个命题换措辞。 | R4/R6 的计量单位写死是「**连续 2 个工具调用**没有新信息」。**没有工具调用 → 计数不增长 → 永不触发**。用户体感"它想很久但没产出"就是这一条。 |
| **D2** | **免责声明替代探测**：回复里出现"可能/大概/取决于/建议你确认一下/这需要看你的配置"，而整条回复**零工具调用**——本可 5 秒探测的事实被转嫁给用户。 | R0 只管「**输入**信息不足」（该不该先问），完全没有规定「**环境/事实**不确定时该先探测还是先免责」。这是"不想就动手"的镜像极端。 |
| **D3** | **无预期即执行 → 归因错位**：跑命令/改文件**之前**没有任何可判定的预期；执行**之后**只看"没报错/没崩"就当成功，不做「预期 vs 实际」对账。后果是改了 A 以为修了 B。 | R5 只在"准备说已完成"那一刻查证据（**事后门槛**）。它不要求动手**前**留下预期，所以中间过程性命令的错配无法被察觉（例如：以为改的是源码，其实 HMR 改的是 `dist/`）。 |
| **D4** | **同一结论重复论证**：第 1 轮给出结论+理由；第 2、3 轮用同义词、加限定词、加免责声明重述同一结论，**没有任何新证据**。 | 与 D1 同源：R4 只数工具调用。没有"结论级去重"的口径，也没有"停论证"的动作定义。 |
| **D5** | **深想触发条件错配**：单文件单点改动写 12 行"实施计划/风险评估/注意事项"；反过来"改 3 个文件 + 改配置 + 重启服务"零计划直接开干。**计划长度与改动面不相关**。 | 全卡没有任何"什么时候需要计划、计划多少行"的规则。R6 只限「次数/时间」，不限「思考产物」。 |
| **D6** | **假设不落地 / 锚定第一假设**：推理里出现"假设是 X"，但既没验证 X、后续行动也没显式依赖 X；只跑过一条支持性验证路径，出现反证就被"可能是缓存/偶发"这类**无证据理由**解释掉。 | R4 的"新信息"定义包含"假设被证实或证伪"，但**没有要求假设必须被写下来**，所以"假设"从不进入计数，被推翻也无人知晓。 |
**共性根因**：现有规则全是「动作计数」型熔断，缺一个「**思考产物必须落成可判定物**」的口径。人类工程师的"想得清楚"之所以可验收，是因为它总是落成"预期 + 判定条件"；模型缺这一层，于是"想"要么退化成免责声明，要么变成表演性的长计划。

## 2. 建议进常驻卡的行（**只 1 行**，逐字可粘贴）
### 2.1 唯一新增行：**新第 8 条**（插在合并后的第 7 条之后、原第 8 行的位置，逐字粘贴）
```text
8. **想清才动手，动手必有预期**：跨 ≥3 模块/改配置/起停进程/不可逆 → 先切**最小可验证切片**（≤1 文件或 ≤1 条命令就能证明方向对不对）再铺开；单文件单点改 → 不写计划直接做；任何有副作用的动作前先写一行 `EXPECT: <动作> → <可观察结果>`（≤40 字，禁计划书），动作后立即对账，不符就改假设并打印 `WHY: <原假设> 错 → 改 <新假设>`，同一假设落空 2 次必换。
```
一条同时覆盖三件事，且三件事在**同一动作序列**里（定档 → 出预期 → 对账）：
| 你点名的能力 | 这一行里的哪半句 | 可观察回执 |
|---|---|---|
| **什么时候该深想** | 「跨 ≥3 模块/改配置/起停进程/不可逆 → 先切最小可验证切片」 | 切片命令与其结果（≤1 文件 / ≤1 条命令） |
| **什么时候必须动手** | 「单文件单点改 → 不写计划直接做」+「动作后立即对账」 | 无计划直接产生改动 + 对账行 |
| **怎么把"想"变成可验收动作** | 「先写一行 `EXPECT: <动作> → <可观察结果>`（≤40 字，禁计划书）」「`WHY: …`」「落空 2 次必换」 | `EXPECT:` / `WHY:`（写在**可见回复**里，不依赖不可见 thinking 段） |
### 2.2 为什么是它，而不是第 2 候选
第 2 候选 = 只写 `EXPECT:` 对账、砍掉前半句（"最小可验证切片 / 单点不写计划"）。**第 1 候选更值这 1 行**，理由是三条硬差别：
1. **只有它同时治「想过头」和「不动脑就上手」两端**。纯 `EXPECT:` 只治后者（无预期的执行）；纯档位只治前者（计划长度失控）。合并后，"想多久"由客观特征决定：单点改 → 0 计划；大改动 → 先切一刀 ≤1 文件/1 条命令。**这是本维度唯一无法被现有 14 条覆盖的部分**——现有卡里没有任何一句提到"计划"或"思考量"。
2. **它把"深想"翻译成动作而不是更多文字**。「切最小可验证切片」的产物是一条**命令或一次改动**，可直接检查；而"先写 ≤10 行计划"的产物是文字，容易退化成计划表演（我的反例清单第 6 条）。这与仓库「删掉它行为不变的不收」一致：切片缺失会直接导致"改完才发现方向错"。
3. **它与 R0/R5 不重叠，且恰好补上两者的缝**：
   - R0 管「**输入**不足 → 零工具调用先问」（用户没给对象+动作）；
   - R5 管「**收尾**时的证据门槛」（宣布完成前）；
   - 本条管「**中间过程**：先想多少、动手前留什么预期、对账不符怎么办」——R0 与 R5 之间那段（也就是 90% 的时间）原本无规则。
   我特意**删掉**了初稿里的"禁把'应该没问题'当结论交付"一句：那句是 R5 的地盘，属于重叠，不收。
### 2.3 零行成本的就地改写（不占行预算，**可选**，逐字替换 `SKILL.md` 第 35 行）
它不新增行，只把第 4 条熔断的计量单位从「工具调用」扩到「工具调用 + 纯推理轮次」——**这是 D1/D4（纯推理空转）唯一的补丁**，因为"纯推理轮次"永远不可能靠新增规则去计数（新增规则本身也不会被计数）。
原文（现第 35 行）：
```text
4. **空转熔断**：连续 2 个工具调用没有新信息 → 打印 `LOOP at N: <动作> x2, 无新信息 → 换 <新维度>`，并换工具/文件/假设/粒度；同一路径连续 2 次 `EPERM`/`ENAMETOOLONG`/"写完文件却消失" → 停手诊断（长路径？杀软？文件被占用？），不许重试第 3 次。
```
替换为（逐字）：
```text
4. **空转熔断**：连续 2 个工具调用无新信息，**或连续 2 轮只有推理、无工具调用、无新事实（同一结论换措辞重说）** → 前者打印 `LOOP at N: <动作> x2, 无新信息 → 换 <新维度>`，后者打印 `STALL at N: <结论> 论证 x2, 无新证据`，然后**三选一**：换工具/文件/假设/粒度，或做 1 条 ≤20 秒的探测拿事实，或直接 `BLOCKED: 需要 <谁> 给 <什么>`；同一路径连续 2 次 `EPERM`/`ENAMETOOLONG`/"写完文件却消失" → 停手诊断（长路径？杀软？文件被占用？），不许重试第 3 次。
```
> 为什么是"就地改写"而不是"另立一条新规则"：D1/D4 与 R4 是**同一场景**（空转熔断），另立一条会造出两条规则抢同一个触发条件，违反 `CONTRIBUTING.md` 反膨胀门槛第 4 条；而且新规则若同样只以"工具调用"计数，纯推理空转照样逃逸。阈值全部沿用现有的 **2 次 / 20 秒**，不引入第二套数字体系。
> 如果你只接受"一处卡面改动"，那就选 §2.1 的那一行；本条留待下一版（代价：纯推理空转仍然不被熔断）。

````markdown
# 推理过程控制附件（什么时候深想 / 什么时候必须停 / 怎么把"想"变成可验收的动作）
> **什么时候读这份文件**（命中任一）：① 任务跨 ≥3 模块、碰配置或环境、起停进程端口、不可逆、已失败 2 次；
> ② 你已经在"想"，但连续 2 轮没有产出；③ 心里冒出"不确定 X"，却不知道该跑哪条命令；
> ④ 用户问"你怎么验证的 / 凭什么说它能用"。
> 通用纪律：**"想"的唯一合法产物 = 一行预期 + 一个可判定结果**。想不出可判定结果，那不是想，是拖。
## 0. 五个数字（本文件的全部硬约束）
| 数字 | 含义 |
|---|---|
| **0 / 5 / 10** | T0 不写计划；T1 计划 ≤5 行；T2 计划 ≤10 行（含失败回退） |
| **≤40 字** | 一行 `EXPECT:` 的长度上限（超过就是计划书，不是预期） |
| **2** | 同一假设落空 2 次必换（卡片第 8 条）；连续 2 轮无新事实必停论证（同卡片第 4、6 条阈值——**刻意不引入第二套数字**） |
| **1 条 / ≤20 秒** | 一次只解一个不确定，用 1 条限定范围的探测命令 |
| **3 条** | 假设台账最多 3 行，每条必须配验证动作或"由用户确认" |
## 1. 什么时候该深想：T0 / T1 / T2 三档
| 档 | 客观触发（可判，不看"感觉难"） | 思考预算 | 必须产出 | 禁止 |
|---|---|---|---|---|
| **T0 直答** | 改动落在**单文件单点** + 可逆 + 首读已给出确定答案 | **0 步计划** | 一行 `EXPECT:` + 行为级验收 | 列计划、写权衡、写"注意事项"、为小事反问用户 |
| **T1 常规** | 改动 ≤3 文件，或 2–5 步 | **≤5 行计划**（步骤 + 每步验收） | 计划 + 每步 `EXPECT:` | 计划 >5 行；有步骤没有验收标准 |
| **T2 深想** | 命中任一：跨 **≥3 模块**或 ≥2 语言；改配置/环境变量；起或停进程、占端口；数据迁移；**不可逆**操作；同一目标已失败 2 次；用户明确说"仔细点/别搞坏" | **≤10 行计划** + 失败回退 | 计划 + **最小可验证切片** + 失败回退 + 风险面 | 没有最小切片就动手；把计划当交付物交给用户 |
**判定口径**
- 档位由客观特征决定；拿不准就**往上取一档**，但**降档必须写理由**：
  `TIER: 由 T2 降 T1 — 只改 1 个文件，已验证无外部依赖`
- **三个立刻升档信号**：出现反证 / 同一动作失败 2 次 / 发现改动面比预想大。
- T2 的硬要求：动手前先切出**最小可验证切片**（≤1 个文件或 ≤1 条命令就能证明方向对不对）。切片没跑通，不许铺开。
- **与卡片的分工**：常驻卡第 8 条只强制两件**必须做**的事——大改动先切切片、任何动作前写一行 `EXPECT:`；本节的"计划 ≤5/≤10 行"是**配套上限**（切片给方向，计划给顺序）。计划行数不是交付物，超了就砍，砍不动说明任务该拆成两个交付。
- 回执：`TIER: T2（跨 3 模块 + 起服务）— 计划 6 步；最小切片 = 先只改 <文件> 跑 <命令>`（`TIER:` 是本附件的回执；只装常驻卡时，用"切片命令 + 其结果"代替）
**正例 / 反例**
- 正例（T0）："把常量 `TIMEOUT` 从 3000 改成 5000" → 直接改，一行 `EXPECT: 改 TIMEOUT=5000 → grep 到 5000，且原 3000 为 0 命中`。
- 反例（T0 写成 T2）：为一个字符串改动输出 12 行"实施计划 / 风险评估 / 注意事项 / 回滚方案"。
- 正例（T2）："给这个项目加登录 + 起服务验证" → 计划 ≤10 行，最小切片 = 先只做 `/login` 路由并 curl 出 200，再铺前端。
- 反例（T2 写成 T0）：改 4 个文件 + 改 `appsettings.json` + 重启服务，零计划直接开干，出错后无法定位是哪一步引入的。
## 2. `EXPECT:` 写法库（一行 ≤40 字，必须能被**一条命令或一次交互**证伪）
| 动作 | 反例（等于没写） | 可判定写法 | 判据（怎么算不符） |
|---|---|---|---|
| 跑构建 | "应该能编译" | `EXPECT: npm run build → 出现 "built in" 且无 error` | 输出里 `error\|ERR!\|failed` 命中数 ≠ 0 |
| 起服务 | "服务起来了" | `EXPECT: 起 vite → 日志出现 "Local:" 且 5173 处于 Listen` | `Get-NetTCPConnection -LocalPort 5173 -State Listen` 为空 |
| 改端口/配置 | "改好了，应该没影响" | `EXPECT: 改 port=3001 → 3001 返回 200，3000 拒连` | 旧端口仍 Listen = 改错了文件 |
| 删/移文件 | "已清理" | `EXPECT: 移走 node_modules → 原路径不存在，备份目录有同名` | 原路径仍存在，或备份里没有 = 丢失风险 |
| 装依赖 | "装完了" | `EXPECT: pip install X → exit 0 且 pip show X 有 Version` | 非 0 退出或 show 为空 |
| 修 bug | "已修复" | `EXPECT: 输入 <x> → 现在返回 <y>（改前是 <z>）` | 结果与 <y> 不同，或没跑过 <x> |
| 改源码/前端 | "改好了，刷新看看" | `EXPECT: 改 src/<f> → 页面源码含 <新字符串>` | 只改了 `dist/`，源码未动或反之 |
**口径**
- 预期必须**可证伪**。写成"能正常运行 / 应该没问题 / 理论上可行" = 没写。
- 一次动作一条预期，不要合并成"以上都应正常"。
- 不符时**先改假设，不要改预期**（改预期去迎合结果 = 自我欺骗）。
## 3. "不确定" → 最便宜的探测（1 条，≤20 秒，中文 Windows）
| 不确定的说法（典型） | 最便宜的探测（可直接粘贴） | 判据 |
|---|---|---|
| "可能是网络/镜像问题" | `Test-NetConnection github.com -Port 443 -InformationLevel Quiet` 或 `curl.exe -I --max-time 8 <url>` | `True` / HTTP 状态码 |
| "大概是编码问题" | `[IO.File]::ReadAllBytes($f)[0..3]` + `chcp` | `EF BB BF` = UTF-8 BOM；`936` = GBK |
| "可能是版本差异" | **复用 R1 探测结果**，不要重跑 | 版本号与所需能力是否匹配 |
| "可能是权限问题" | 对该目录做一次写测试（写临时文件后删） | 成功 / `EPERM`、`Access denied` |
| "可能是缓存 / HMR 失效" | `curl.exe -s http://localhost:<port>/<path>` 看返回体是否含新字符串 | 含/不含，直接判 |
| "可能是杀软 / 文件被占用" | 看 `%TEMP%` 写入是否消失 + `Get-MpPreference \| Select-Object -ExpandProperty ExclusionPath` | 文件消失 = 有拦截 |
| "不确定这个函数在哪被调用" | `Select-String -Path .\src -Pattern '<名>' -Encoding Default`（限定目录） | 命中行号；0 命中 ≠ 不存在（换词/换编码） |
| "不确定用户想要哪个方案 / 目标路径" | **探测解决不了** → 一次提问或 `BLOCKED:`（与 R0 一致，只问 1 次） | 用户给了决策才算解除 |
**口径**
- 一次只解一个不确定。**禁止**把 3 个不确定堆成一段"分析"——那是一段免责声明的变体。
- 探测命令同样受 R2 成本上限约束：限定目录 + 深度 ≤3 + 超时 ≤20 秒。
- 结果一行回执：`PROBE: <命令> → <结果>`；**0 命中或报错也是结果**，直接用它决定下一步。
- 同一探针 2 次都没给出可判定结论 → 换维度（换工具 / 换证据类型 / 换粒度），第 3 次必须 `BLOCKED:`。
## 4. 假设台账（回复里 ≤3 行，不落盘、不建文件）
```text
ASSUME1: <事实性假设> | 验证: <一条命令或"由用户确认"> | 状态: 未验 / 成立 / 推翻
ASSUME2: ...
RISK: <若 ASSUME1 成立不了，会怎样>
```
**口径**
- 假设 ≤3 条；每条必须配一个验证动作，或显式写"由用户确认"（不许留白）。
- **被推翻的假设必须写在下一轮开头**：`WHY: 原假设<X>错 → 改<Y>`。沉默地换方向 = 让用户无法审计。
- 假设一旦进入台账，后续行动要**显式依赖**它（引用编号）；不依赖的假设删掉，别挂着。
- 反例：通篇"可能是…也可能是…"（没有任何一条被验证过），最后给一个模棱两可的结论。
## 5. 停止规则（比"多想想"更重要）
| # | 触发（客观） | 动作 |
|---|---|---|
| 1 | 同一结论第 2 次重述，且无新证据 | 停论证：探测 1 条，或 `BLOCKED: 需要 <谁> 给 <什么>`（对应卡片第 4 条；若宿主未吸收该口径扩展，就按本条自行执行——它就是本条存在的理由） |
| 2 | 连续 2 步没有产生"外部可观察的变化"（文件、输出、状态） | 写 `CHECKPOINT:`，然后**降级到最小可验证切片** |
| 3 | 计划已经超过 10 行 | 停：说明为什么砍不到 5 行；砍不动就说明任务该拆成两个交付 |
| 4 | 出现反证 | 先记录该反证；**禁止**用"可能是缓存/偶发/环境问题"解释掉（无证据的解释 = 空转） |
| 5 | 同一条探针 2 次都无结论 | 换工具/换证据类型/换粒度；第 3 次必须 `BLOCKED:` |
| 6 | 已在同一假设上花了 >5 步 | 强制写一句"这个假设如果错了，替代方案是什么"；写不出 → `BLOCKED:` |
**沉没成本**：进入同一路线的步数**不**构成继续的理由。规则只认"下一步能否产生可观察的新事实"。
## 6. 反例：会让模型更笨的写法（成对给替代）
| 会变笨的写法 | 为什么 | 替代 |
|---|---|---|
| "先仔细想想再动手"（无数字无回执） | 模型把"想"实现成长篇免责声明与权衡 | `EXPECT:` 一行 + 档位表（想多少由档位定） |
| 要求"输出完整推理过程/写满 10 条思路" | 长计划变表演；且 CoT 可能与真实决策不一致（见 §7），长度换不到正确率 | 计划 ≤5 行，每步带可观察验收 |
| "不确定就问用户" | 把 5 秒可探测的事转嫁给用户（D2） | 先探测；只有"信息只有用户有"才问，且只问 1 次 |
| "多验证几次/反复确认" | 与 R6 冲突，诱发重复部署循环；无外部反馈的自我检查可能**降低**表现（§7） | 每条预期只对账 1 次；不符即改假设 |
| "如果没把握就加免责声明" | 把 D2 制度化 | 免责声明只在 R5 的"本机无法验证"出口使用，且必须附确切验证步骤 |
| 把"计划"当交付物返回 | 用户要产物，不要过程 | 计划留在过程里，交付物照原要求给 |
| 对 T0 任务强制"先给方案再等确认" | 小事变慢，用户会关掉插件 | T0 直接做，只在不可逆时走 R11 闸门 |
| 规则里写"要深入思考、要严谨" | 删掉它行为不变 → 不满足反膨胀门槛 | 写触发 + 数字 + 回执 |
````

## 4. 反例：什么写法会让模型更笨（卡片/文档层面的红线）
1. **无数字的"深度"指令**——"仔细想""深入分析""充分评估"。模型无法把它们变成动作，只能变成更多文字。**必须换成一行可判定物。**
2. **要求把推理过程写进输出**——推理长度与正确率不是单调关系（`§6` 证据 2/3）；且自述理由可能不忠实（证据 5）。**只认外部可观察回执，不认"我分析认为"。**
3. **"不确定就先问用户"**——把 5 秒可探测的事推给用户，制度化 D2。
4. **"多想几轮/自我检查 2 次再交付"**——无外部反馈的自我纠错可能**降低**表现（证据 4），且与 R6 冲突。
5. **把"计划"当交付物**——回复只有步骤没有产物，用户感知是"更啰嗦"，不是"更聪明"。
6. **对琐碎任务也强制计划/确认**——T0 被当成 T2，插件会被用户卸载。**档位必须由客观特征判定。**
7. **给"思考"设一个无上限的口子**（如"直到完全想清楚为止"）——这正是 D1 的成因，必须给"2 轮 / 2 次"的硬停。
8. **在卡片里写两套阈值**（比如新增规则用 3 轮、旧规则用 2 次）——模型和用户都记不住两套数，遵守率下跌。**全部沿用 2 / 2 / 20 秒。**

## 6. 证据
**论文 / 官方文档（已核对原文摘要）**
1. **Overthinking**（arXiv:2412.21187，*Do NOT Think That Much for 2+3=?*）：o1 类模型在简单题上分配过多算力、收益极小；提出过程/结果两个效率指标。→ 支持**按难度分档给思考预算**，且「想更多」不是免费的。 [链接](https://arxiv.org/abs/2412.21187)
2. **s1 / budget forcing**（arXiv:2501.19393）：**强制终止**模型的思考过程（或反过来追加 "Wait"）可以控制测试时算力，且强制终止常让模型"复查答案"从而修正错误推理。→ 支持**给"想"设硬停并在到点时输出结论**，而不是让思考自然收敛。 [链接](https://arxiv.org/abs/2501.19393)
3. **The Illusion of Thinking**（arXiv:2506.06941，NeurIPS 2025）：LRM 在复杂度超过某点后准确率**完全崩塌**；推理努力随复杂度先增后**降**（还有 token 预算时也停止思考）；且低复杂度任务上标准模型反而更好。→ 支持**T0 档不写计划**（低复杂度上"多想"是负收益）与"停止规则必须外置"（模型自己不会在正确时机停）。 [链接](https://arxiv.org/abs/2506.06941)
4. **LLMs Cannot Self-Correct Reasoning Yet**（arXiv:2310.01798，ICLR 2024）：**没有外部反馈**时，模型难以自我纠错，有时自我纠错后表现**下降**。→ 直接否定"多自我反思几遍"类规则；支持把"停 + 外部探测"写进硬规则（本维度的 `EXPECT:` / 探测映射 / `BLOCKED:`）。 [链接](https://arxiv.org/abs/2310.01798)
5. **CoT unfaithfulness**（arXiv:2305.04388，NeurIPS 2023）：CoT 解释可以**合理但不忠实**——模型会为已有（被偏置的）答案编造理由而不提真正原因，准确率最多掉 36%。→ 支持"只认外部可观察回执（文件哈希、命令返回、状态变化），不认自述理由"；也给"不要要求模型输出完整推理过程"提供了依据。 [链接](https://arxiv.org/abs/2305.04388)
6. **ReAct**（arXiv:2210.03629，ICLR 2023）：推理与行动**交错**（reason → act → observe）在 HotpotQA/Fever 上克服了纯 CoT 的幻觉与错误传播，在 ALFWorld/WebShop 上成功率分别高 34%/10%。→ 支持"预期（reason）—执行（act）—对账（observe）"的最小闭环，即 `EXPECT:` 的结构依据。 [链接](https://arxiv.org/abs/2210.03629)
8. **Anthropic「think」工具工程博客**（2025-03-20）：τ-bench airline 域 pass^1 从 baseline **0.332** → 仅提供工具 **0.404** → 工具**+优化提示** **0.584**；SWE-bench 上 think 工具带来 1.6% 平均提升（p<.001, d=1.47）。同一文章明确两点：**① 只开工具不给"什么时候想、想什么"的提示，收益有限**；**② 对非顺序工具调用与简单指令跟随无收益，还增加 token**。→ 这两点正是本维度那一行的两条腿：规则必须写死"何时想 / 想多少"（只喊"要思考"拿不到收益），且**简单任务必须明令不写计划**（否则等于给所有任务加税）。 [链接](https://www.anthropic.com/engineering/claude-think-tool)
**推理（我的判断，标注推测）**
- **推测 A**：「连续 **2** 轮无新事实」与「同一假设落空 **2** 次」这两个阈值是工程选择，非实验结论。选 2 的理由是**与现有 R4/R6 阈值体系对齐**——引入第二套数字（例如 3 轮）会让模型和用户都记不住，遵守率下降。可用 P13–P16 在多模型上跑几轮后调整（2 轮是否过严，在慢模型上待验）。
- **推测 B**：T0/T1/T2 的分档边界（单文件 / ≤3 文件 / ≥3 模块或不可逆）是根据仓库既有措辞（R3 的"同文件 2 次"、R6 的列表）与桌面端常见任务形状推出的，**未做实测标定**。
- **推测 C**：P13–P16 的判定阈值为我设计，未经跨模型验证；P14 的"≥3 轮零工具调用"判据刻意设得比规则的 2 轮松，是为了降低误判（允许一轮正常澄清）。
- **推测 D**：国产模型（DeepSeek / Qwen / GLM / Kimi / 豆包 / 文心 / 混元 / MiniMax）在长 CoT 上更容易出现"重复论证 + 免责声明"组合（D1+D2+D4）——属**经验观察，未实测**。它们多数把 thinking 与 answer 分离，规则生效点可能在 thinking 段不可见；因此本维度所有回执都要求写在**可见回复**里（`EXPECT:`/`STALL at`/`BLOCKED:`），不依赖 thinking 段。这一点对国产模型尤其关键。
- **推测 E**：`EXPECT:` 对"减少返工"的净收益大于"多写一行的成本"——依据是 Anthropic 的 think-tool 结果（显式提示才拿到主要收益）与 MAST 的验证类失败占比，但**没有直接的 A/B 实验**。

## 7. 诚实边界（沿用仓库既有立场，不夸大）
- 本维度是**指令层**方案：能显著提高遵守率（有数字、有回执、可被用户当场质询），但**不保证模型一定遵守**；要 100% 拦截需宿主层钩子（与 `docs/why-ai-work-doctor.md §8` 一致）。
- 对**把 thinking 藏在不可见通道**的宿主/模型，只有"可见回复里的回执"能被检查；卡片的回执设计已按此约束做了（全部要求出现在可见输出里）。
- 规则**不提升参数量与预训练能力**；收益来自"不再犯蠢"（少空转、少归因错位、少把不确定转嫁给用户），不是"变天才"。
- 我没有跑 `eval/` harness（需要宿主与真实对话轮次），P13–P16 是**设计**而非实测数据；`§6` 中标注"推测"的部分请按探针结果再定阈值。
