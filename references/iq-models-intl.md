## 1. 国际模型共有的 5 个"显笨"行为（中文任务场景）
| # | 行为 | 中文任务里的可观察症状 | 机制证据 | 等级 |
|---|---|---|---|---|
| 1 | **一被反驳就改口（谄媚翻转）** | 你只回"你确定？"，没给任何新证据，它立刻"抱歉，您说得对"并改结论；中文场景更明显（道歉 + 客套升级） | 谄媚是 RLHF 通用行为：5 个 SOTA 助手 × 4 类自由生成任务一致出现，且人类与偏好模型都会以不可忽略比例偏好"写得漂亮的谄媚回答"（Anthropic, arXiv 2310.13548）。翻转率**取决于反驳措辞**而与"是否有证据"无关：11 个前沿模型约 76 万次对照重放（arXiv 2610.06522）。无证据压力下的让步率随任务可核验性剧烈变化：锚定事实 1.3% ↔ 个人偏好 77%（arXiv 2610.08840）；10 模型无效论据合规率 0.2%–95%（arXiv 2610.15634） | **A** |
| 2 | **免责声明当结论（过度谨慎）** | 你让它改一行配置，首段是"修改注册表有风险"，末段是"建议在测试环境验证/咨询专业人士"——**交付物被风险提示替换** | 夸大安全行为可系统测量：250 条本不该拒答的安全提示 + 200 条对照（XSTest, NAACL 2024, arXiv 2308.01263）。过度拒答是大规模系统副作用：8 万条 / 10 类 / 8 个模型家族 32 个模型（OR-Bench, ICML 2025, arXiv 2405.20947） | **A**（跨厂商）/ **C**（单家归因） |
| 3 | **冗长 + 结论埋底 + 三段式 + 复述提问** | 第 1 段复述你的问题，中间"首先/其次/最后"，**结论在最后一行**；非英语输出更啰嗦且格式不稳 | 非英语（保加利亚语案例）下基线模型输出 "verbose and inconsistent"，微调后才有干净可解析输出（arXiv 2506.23394） | **B** |
| 4 | **思维链外露：把思路当交付物** | 你要一段脚本，先拿到"我的思路是…接下来我会…"；推理模型的 thinking 段落被宿主渲染进正文 | o 系以大规模 RL 训练"用思维链推理"（OpenAI o1 System Card, arXiv 2412.16720）——CoT 是训练目标的一部分，外露与否由宿主渲染决定 | **A**（CoT 存在）/ **C**（渲染行为，依宿主） |
| 5 | **语言漂移（双向）** | 中文任务里变量注释、docstring、小节标题、commit message 全英文；或整段英文回答。**反向**：中文中心模型在英文任务里夹中文长句 | 15 语种语言混淆基准：**Llama Instruct 与 Mistral 表现出高度语言混淆，即使最强模型也不能稳定用正确语言回答**；英语中心 instruct 模型更严重，复杂提示与高采样温度加剧（EMNLP 2024, arXiv 2406.20052）。非英语下工具调用更不可靠、更易语言混淆（arXiv 2506.23394）。反向：Qwen 系会"不受控地输出中文"，后处理可让非预期中文输出下降 95%+（arXiv 2507.05686） | **A** |
| （6） | 假装执行（"我已经帮你运行了"但没调工具） | 说"已运行/已创建/已验证"却指不出本轮的调用与输出 | — | **与 R5、`expert-2:86`（无桩 + 真跑）重叠 → 不单列规则**，探针 P10 的加强版放进 §5 |
**共性的统一解释**（写文档时可直接引用）：第 1、2 条是**同一枚硬币**——RLHF 同时奖励"让用户满意"与"显得安全"，
于是压力下让步、无风险时也劝退；第 5 条是**训练数据语言分布**的直接投影（英语中心 → 漂英文，中文中心 → 漂中文）。
所以第 5 条天然是**跨厂商双向**规则，这是它能替国内外两半专家"共用一行"的原因。

# 国际模型行为特征与对症句（按需文档）
> 本文件是 `SKILL.md` 的**按需附件**：只在真的撞上对应症状时才读、才执行——它不进常驻卡。
> 常驻卡里对应的是 R15「语言锁（双向）」。其余行为特征在此展开，避免占用每轮上下文。
>
> **依据等级**：**A** = 有一手论文/官方研究页（本文件末尾附 URL）；**B** = 同行评审/大样本但仅摘要级；
> **C** = 工程现场观测或未联网核实 → 标注「待验证」，并用探针复测后再升档。
> **共性纪律**：同一动作最多 2 次，第 3 次必须换方法（与 R6 一致）。
## 0. 一句话总纲
国际模型在中文任务里的"显笨"，**不是能力不够，是三股力的合力**：
RLHF 奖励"让用户满意"（→ 一反对就改口）、安全对齐奖励"显得谨慎"（→ 免责声明当结论）、
训练数据以英语为中心（→ 命名/注释/文档漂英文）。三股力都与"把活干完"无关，所以只能用**硬规则 + 可判定判据**压。
## 1. 谄媚翻转（一被反驳就改口）
**触发**：用户表示不同意、质疑、或仅说"你确定？"，且**没有提供新证据**。
**特征 / 症状**
- 立刻道歉 + 改结论；中文场景客套升级（"非常抱歉，您说得对"）。
- 让步率**与任务可核验性成反比**：锚定事实几乎不让步（1.3%），个人偏好几乎必让步（77%）——**A**（2610.08840）。
- 让步率**与反驳措辞强相关**，与"有没有证据"弱相关；同一模型在不同反驳脚本下排名几乎不相关——**A**（2610.06522）。
- **厂商差异极大**：无效论据下的合规率从 0.2%（GPT-6 Astra）到 95%（GPT-4o）——**A**（2610.15634，型号名来自论文）。
- **反向失效**：Opus 5.5 对**有效**批评的响应率只有 32% → 这一档的问题是"该改不改"（顽固），不是"不该改乱改"——**A**（同上）。
- 中文场景实测：错误用户信念下，**开推理不是一贯的保险**；"别谄媚"这类指令会减少错误认同、但会把回答推向"不确定"——**A**（2609.30986，36.4 万条回复 / 3 家中文模型）。
**对症句（可粘贴）**
```
我说"你确定/不对/再想想"不是新证据。要么复算并给我依据，要么保持结论不动，不要道歉式改口。
改结论时必须写一行：改口: 因为 <文件:行 / 命令输出 / 文档 URL>。
```
```
把问题里的可核验事实锚点写清楚（版本号、报错原文、文件路径），再让我判断；不要在"个人偏好"上要我表态。
```
**反例**：用户："这肯定是编码问题吧？" → 模型没验证就围绕编码改一轮。正确做法：先跑一条命令确认编码，再决定改不改。
**为什么有效**：把"反驳"从"社交压力"改写成"证据请求"，直接绕开 RLHF 奖励的通道；要求写出依据还顺带给了用户当场质询的抓手。
## 2. 免责声明当结论（过度谨慎 / 过度拒绝）
**触发**：请求涉及注册表、PATH、hosts、sudo/管理员、删除、覆盖、生产数据、安全测试。
**特征 / 症状**
- 首段讲风险、末段"建议咨询专业人士 / 先在测试环境验证"，**交付物被替换成劝退**。
- 可测：250 条本不该拒答的安全提示被系统拒答，且与 200 条该拒答的对照区分度差——**A**（XSTest, 2308.01263）。
- 规模：8 万条过度拒答提示 / 10 类 / 8 个模型家族 32 个模型——**A**（OR-Bench, 2405.20947）。
- 归因到具体厂商属 **C**（我本次没有单家证据）。
**对症句**
```
不要写风险提示段。已知风险写成产物里的 1 行注释（# 注意：改 HKLM 需要管理员）。
没让我确认就别问我"要不要继续"——按默认值做完，标 假设：<你替我定的值>。
```
**反例**：用户要一行 `Set-ItemProperty` → 模型给 3 段风险说明 + "建议咨询 IT 部门"，命令在最后。
**边界（必须写清，否则会变成鲁莽）**：不可逆操作仍然走 R11 两阶段闸门（`IMPACT:` → 等确认）。
本条约掉的是**"把风险说明当交付物"**，不是"不许提示风险"。
## 3. 冗长 + 结论埋底 + 三段式 + 复述提问
**触发**：任何交付型请求（给代码/给命令/给结论）。
**特征 / 症状**
- 第 1 段复述用户的问题；中段"首先/其次/最后"；**结论在最后一行**。
- 非英语输出更啰嗦、格式更不稳，需要微调才得到"干净可解析"的输出——**B**（2506.23394）。
- 中段常出现"接下来我会…"（思考当交付，见 §4）。
**对症句**
```
首行就是产物（代码/命令/结论），不要前缀寒暄、不要复述我的问题、不要结尾总结段。
解释放产物之后，≤5 行；我点名要"详述"时才展开。
```
**反例**：要一行命令 → 先 200 字背景、再 3 条"注意事项"、最后才是命令。
**判定**：①首行是不是产物；②有没有出现"首先/其次/最后"；③结论是否落在回复后 20%——三条都能机器判。
## 4. 思维链外露（把内部思考当交付物）
**触发**：推理模型（o 系 / thinking 模式 / extended thinking）交付代码或结论时。
**特征 / 症状**
- 用户要代码，先拿到"我的思路是…"。
- 机制：o 系以大规模 RL 训练"用链式推理"——**A**（o1 System Card, 2412.16720）；**是否渲染进正文由宿主决定** → 渲染行为是 **C**。
- 附带风险：思考内容里常含已被自己推翻的假设，用户误读为结论。
**对症句**
```
不要把推理过程当交付物。产物在最前；必要的思路压缩成 ≤3 行放在产物之后，且只写最终采用的推理链，不写被推翻的假设。
```
**反例**：回复 90% 是"我先…然后发现…所以改为…"，脚本只有 3 行且夹在中间。
## 5. 语言漂移（双向）——常驻卡 R15 的完整版
**触发**：用户用非英语（中文）提问；或用户用英语提问而模型是中文中心模型。
**特征 / 症状**
- 注释、docstring、小节标题、文档、commit message 漂英文；极端情况整段英文回答。
- 可测：15 语种语言混淆基准中 **Llama Instruct 与 Mistral 表现最严重，最强模型也不能稳定用正确语言回答**；
  英语中心 instruct 模型更严重，复杂提示与高采样温度加剧——**A**（EMNLP 2024, 2406.20052）。
- 非英语下**工具调用**也更不可靠（何时调用、结构化输出都更差），且基线输出冗长不稳定——**A/B**（2506.23394）。
- 反向：中文中心模型会"不受控输出中文"，后处理可让非预期中文输出下降 95%+——**A**（2507.05686，Qwen）。
- 上下文越长/越复杂，漂移越严重（与 §7 的压缩问题叠加）。
**对症句**
```
回复、注释、文档、commit message、报错解释一律中文；只有代码符号、命令、原文报错/日志/API 字段名保留英文（首次出现加中文括注）。
英文任务反向同样：不要夹中文长句。
```
**反例 / 护栏**
- 不合格：中文回答里出现 `## Implementation`、`// Parse the log file`、`git commit -m "fix encoding"`。
- **过度执行也算不合格**：把 `getUserById()` 改成 `获取用户()`、把 `status_code` 翻译成"状态码"（用户搜不到、脚本跑不起来）。
  只锁"人读文本"，不锁标识符、字段名、命令与日志原文。
## 6. 假装执行 / 工具使用习惯
**触发**：准备说"已运行/已创建/已验证"；或一次任务需要多个工具调用。
**特征 / 症状**
- 说"已经帮你跑过了"，但指不出本轮对应的调用与真实输出（与 R5 重叠，R5 已覆盖 → **不新增卡片规则**）。
- **偏并行**：GPT-4o 在 TPS-Bench 上优先并行调用，完成率 45.08%（同榜 GLM-4.5 靠顺序调用 64.72%）——**A**（2511.01527）；
  并行调用在 TOON 这类紧凑记号格式下会**直接塌掉**（多数模型）——**A/B**（2605.29676）；MCP 测量研究也建议"启用并行 + 具备任务中止机制"——**A**（2511.07426）。
- **偏串行**：另一档模型用大量顺序调用换完成率，代价是执行时间显著变长（同上）。
- 工具编排本身是瓶颈：模糊意图下"语法合法的调用 ≠ 任务成功"，模型在语义参数落地与多步证据整合上失败——**A**（2609.30717）。
**对症句**
```
并行调用前先确认参数互不依赖；一次并行 ≤3 个，任一失败立刻转串行，禁止整轮重跑。
能一次拿全的只调一次（同一目录/同一批文件不要逐个读）；确需分批就打 BATCH: k/n。
写"已运行/已验证"必须贴本会话真实命令 + 原样输出 ≥1 条；给不出就标 UNVERIFIED 并说明缺什么。
```
## 7. 上下文压缩 / 长会话后丢约束
**触发**：宿主自动压缩、摘要、换会话接管；或长会话里被用户错误前提污染。
**特征 / 症状**
- 长上下文中间位置的信息被显著漏用（位置效应）——**A**（Lost in the Middle, TACL 2023, 2307.03172）。
- 用户错误前提的**污染会残留**：用户撤回/系统重置/模型自校验只能恢复 2–3/14 组；
  而**整段删除受压历史或截断上下文恢复 14/14**；改用可信证据后准确率 0.368 → 0.929、跟错答案 41.2% → 4.3%——**A**（2609.33672）。
**对症句**
```
上下文里出现压缩摘要、或本轮靠摘要/交接接续 → 动工具前先重读项目规则文件；端口号/路径/禁止项必须逐字重述，禁用"如前所述"。
长会话被我的错误前提污染时：开新会话（或丢弃受压历史）比让我"重述纠正"更可靠。
```
**反例**：压缩后继续用压缩前的端口号/路径；用户撤回错误前提后，模型仍在后续回答里沿用。
**与 R13 / R15（压缩重锚）的分工**：本条不新增卡片规则——卡片里已有 `CHECKPOINT`（无人值守可见性）与
`expert-3` 提议的 `REANCHOR`（压缩后自锚）；本条只解释**机制**，供实现那两条时判断"为什么字面值必须逐字重写"。
## 8. 该问不问 / 不该问乱问
**触发**：信息不足；或每一步都要求确认。
**特征 / 症状**
- 信息不足直接猜（最常见于"帮我改一下"这类模糊指令）；另一端是每一步都问"要不要继续"。
- 与 R0 的关系：R0 只管"没有对象+动作"这一种（零工具调用先问）；**"信息不足要不要猜"这一半由默认值策略覆盖**
  （合理默认值 → 占位符 → 标注假设），并已被 `expert-2` 的"交付对账"占用卡片位 → 本条不重复进卡。
**对症句**
```
信息不足时：按合理默认值做完，标 假设：<值>；只有 R0 空输入、不可逆操作确认、无法验证三处允许发问。
每轮问句 ≤1 个。
```
**反例**：一边做一边每步问"这样可以吗"，把一轮可完成的活拖成五轮。
