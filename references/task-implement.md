# 任务型协议：实现（新功能 / 新模块 / 新接口）

## 完成定义

1. **接口先行**：函数签名/入参出参/错误语义先定下来（哪怕写在注释里）。
2. **最小可验证切片**：先跑通一条最窄的路径，再扩展；不要一次性写完 5 个文件再跑。
3. **行为验收**：不是"编译通过"，是"给定输入产出预期输出"（贴命令 + 原样输出）。
4. **边界清单**：空/单元素/重复/超长/异常输入各一条，至少覆盖 3 个。

## 3 个检查点

- **CP1 先看邻居**：同目录已有实现风格（命名、错误处理、日志），照抄约定，不发明新风格。
- **CP2 依赖先探**：要用到的库/版本/命令先确认存在，别写完才发现不可用（第 4 条事实闸门）。
- **CP3 一次只让一个测试变绿**：红了先看是谁的错（第 3 条），不要为了绿改业务。

## 常见翻车

| 翻车 | 症状 | 正确做法 |
|---|---|---|
| 先写一堆再跑 | 10 个错误一起爆，定位成本翻倍 | 窄路径先绿，再往外扩 |
| 桩代码当实现 | `TODO`/空函数体 → 交付即假 | 新增空体必须点名并说明何时补 |
| 接口与调用方不一致 | 自己测试绿，集成炸 | 改签名前搜旧名（第 10 条） |

## 退出条件

目标路径行为验收通过 + 边界覆盖 ≥3 → 交付；需求有歧义 → 用合理默认值并标 `ASSUME:`，不要卡住等回复。
