# 任务型协议：总索引（先分型，再套检查点）

> 一句话：不同任务的"完成"定义不同，用同一套验收标准是浪费也是漏检。
> 卡内只有一行路由，具体协议按需加载——不占每轮预算，也不会互相串味。

## 怎么用（3 步）

1. **判型**：这条任务主要是什么？调试 / 实现 / 重构 / 调研 / 运维。
2. **只读该型**：加载对应 reference，照它的"完成定义"验收；跨型的任务按阶段切，一次只用一型。
3. **交付时对表**：该型的完成定义逐条打勾，缺哪条明说。

## 五型对照

| 型 | 主协议页 | 完成定义的核心 | 最容易假完成的地方 |
|---|---|---|---|
| 调试 | [task-debug.md](task-debug.md) | 失败的复现 → 根因 → 同复现转绿 | "报错消失了"当成修好 |
| 实现 | [task-implement.md](task-implement.md) | 接口先行 → 窄切片 → 行为验收 | "编译通过"当成做完 |
| 重构 | [task-refactor.md](task-refactor.md) | 前后同测一致 + diff 半径 | 重构里夹带行为变更 |
| 调研 | [task-research.md](task-research.md) | 结论 + 可追来源 + 不确定项 | 罗列一堆不给结论 |
| 运维 | [task-ops.md](task-ops.md) | 先数后动 + 回滚点 + 复核同数 | 影响面没数就动手 |

## 判型的边界

- **跨型任务**（如"实现新功能并部署"）→ 切成两个阶段，各自套协议，交付时分别对表。
- **判不出来** → 按实现型走，并在交付时说明"我按实现验收"，不要含糊。
- **纯问答/解释类** → 不套任何型，直接给结论 + `file:line` 即可（卡第 3 条）。
