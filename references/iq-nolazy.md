### 2.2 为什么是这一行（而不是第 2 候选"对账 + 不留问句"）
满足 `CONTRIBUTING.md:7` 三要素：**触发** 任何多要求任务收工前 / 准备写"已运行"时；
**动作** 编号回抄对账 + 扫新增行桩代码 + 贴本会话命令与输出；
**数字上限** N=用户条目数、桩命中 0、真实命令+输出 ≥1 条、UNVERIFIED ≤ 总数 1/3；
**回执** `DONE m/N`、`NOSTUB: <文件:行>`、`UNVERIFIED: <入口>`。
它比第 2 候选（"对账 + 禁止收尾问句"）值这 1 行的 5 个理由：
1. **同样 1 行，它覆盖 3 类偷懒（D1/D2/D4），第 2 候选只覆盖 1 类（D7）**。这一组正是"能否偷懒"的
   机械判定核心，也是本维度相对 R5 的独有价值。
2. **它买的是"用户看不见的坏"**。D1/D2/D4 的共同特征是**看不出来**：代码看着齐、话说得很确定，
   用户要等到下次构建、下次上线或被别人 review 时才发现，纠正成本高一个数量级。D7（问句）是
   **可见**的，用户当场回一句"做完"即可纠正，成本 1 秒；且宿主侧已有约定在压问句
   （R0 的"零工具调用先问"是另一端的同一件事）。预算该买贵的那个。
3. **可机械判定性**：本行的三个信号都能脚本化 —— N 是计数、桩扫描有实测可跑的命令（§3.2）、
   "命令 + 原样输出"是存在性检查。而第 2 候选的"这个问句该不该问"要求先判断"该动作能否按默认值
   完成"，是**主观判定**，与 `CONTRIBUTING.md:7` 的"写不出数字上限的不收"精神不符。
4. **它封住了 D2 的根源攻击面**：只要 N 的定义权留给 agent，它就会把 5 条缩成 2 条（"核心功能已实现"）。
   所以必须写死"**逐条回抄原句**"。第 2 候选没有这个攻击面意识。
5. **附带的反 gaming 数字**：`UNVERIFIED ≤ 总数 1/3` 专门防"全标 UNVERIFIED 免责"，并补一句
   "能在本机跑通却标它 = 未完成"。没有上限的话，这条规则会被用成免罪符（这是本设计的已知攻击面，
   见 §6 P2）。
**为什么不并进 R5**：R5 是一张"按改动类型给证据"的表；把数量对账 + 桩代码 + 命令原文塞进去，
会让那一行超过现有最长行（第 2 条 ≈260 字符）且语义混杂（类型 vs 数量/真实性）。
`CONTRIBUTING.md:10` 说"同一场景只留一条"——这两者不是同一场景。

## 3. 建议放按需文档 `references/iq-nolazy.md`
> 设计原则同 `desktop-cn.md`：**命中才读**，每条给命令或判定式，不给口号。
> 命令按中文 Windows + PowerShell 5.1 写。本机实测 **`rg` 不存在**（§6 E4），故一律 `Select-String` 兜底。
### 3.1 连带影响（D3）
**触发**：`git diff` 命中定义行（函数/类/导出名/配置键/默认值）。
```powershell
# ① 列出本次改动的"接口行"（-U0 只出改动块，避免整篇 diff 进上下文）
git -c core.quotepath=false diff -U0 > "$env:TEMP\aiw.patch"
Select-String -Path "$env:TEMP\aiw.patch" -Encoding UTF8 -Pattern '^[+-].*(def\s+\w+|function\s+\w+|class\s+\w+|export\s+|const\s+\w+\s*=|"[A-Za-z_][A-Za-z0-9_]*"\s*:)'
```
```powershell
# ② 对每个被改的旧符号搜一次（限目录 + 限深度 + 排除产物目录）
Get-ChildItem -LiteralPath .\src,.\tools,.\docs -Recurse -Depth 3 -File -Include *.ps1,*.ts,*.py,*.md,*.json |
  Select-String -Pattern 'OldSymbol' -Encoding Default
```
- **判定**：旧符号命中 = 0（已全部迁移）**或**每条命中都出现在交付清单里（`文件:行`）；有命中却没列 = 未完成。
- **数字上限**：同一符号搜 ≤2 次（与 R2/R6 一致）；调用点 >20 处 → 先列清单再批量改，禁止逐个试错。
- **回执**：`RIPPLE: <符号> 调用点 n 处，已改 <清单>` 或 `RIPPLE: <符号> 0 命中`。
- **反例**：只改 `.tsx` 忘了同名的 `.d.ts` 与 `docs/` 示例；把旧符号留在注释里冒充"0 命中"
  （故要看命中**上下文**，不能只看计数）。
### 3.2 桩代码 / 空函数体扫描（D1，**命令已实测可跑**）
```powershell
git -c core.quotepath=false diff -U0 > "$env:TEMP\aiw.patch"
$added = @(Get-Content -LiteralPath "$env:TEMP\aiw.patch" -Encoding UTF8 | Where-Object { $_ -match '^\+' })
# ① 关键词（高召回）
$added | Select-String -Pattern 'TODO|FIXME|XXX|NotImplemented|^\+\s*(pass|\.\.\.)\s*$|待实现|待补充|后续可扩展|暂不支持|你自己补'
# ② 结构（空体：定义行紧跟 pass / return None / } / ... ；或单行 {} ）
for ($i=0; $i -lt $added.Count; $i++) {
  $cur = $added[$i]
  if ($cur -match '^\+.*(def\s+\w+|function\s+\w+|\w+\s*[:=]\s*(function\s*)?\([^)]*\)\s*(=>)?\s*\{)') {
    $nxt = if ($i+1 -lt $added.Count) { $added[$i+1] } else { '' }
    if ($nxt -match '^\+\s*(pass|return\s+None|return\s+null|return;|\}|\.\.\.)\s*$' -or $cur -match '\{\s*\}\s*;?\s*$') { "EMPTY: $cur" }
  }
}
```
- **判定**：两类命中都必须出现在 `DONE` 的"未做项"或 `NOSTUB: <文件:行>` 里，否则按未完成算。
- **数字上限**：新增行桩命中 = 0 才算完成；豁免只能写进"未做项"并逐条给原因。
- **实测记录（本机 PS 5.1.19041.6456）**：`+    pass`、`+def g(y):`+`+    return None`、
  `+function h() {}`、`+const k = () => {};`、`+    // 后续可扩展` 全部命中；普通闭合行 `+        }`
  **不误报**（误报 0）。
- **反例（必须写进文档）**：只查英文 `TODO` 会被 `// 后续可扩展`、`暂不支持`、`先返回默认值` 绕过 →
  词表必须中英混排（已含）。
### 3.3 边界与错误路径 6 类（D5）
| 类别 | 一条可执行探针（PS 5.1） | 通过标准 | 失败信号 |
|---|---|---|---|
| 空 / 缺失 | `& $exe ''`；`& $exe -Path 'C:\不存在\x.txt'` | 明确错误信息 + 非 0 退出码 | 裸 traceback / 静默"成功" |
| 超长 / 超限 | `& $exe ('中' * 100000)`；100 万行输入 | 有上限校验或分块 | OOM / 卡死 >20s（触 R6） |
| 权限 | `Set-ItemProperty $f IsReadOnly $true` 后跑，再复原 | 清晰报错且不吞异常 | 崩在中间态 / 静默跳过 |
| 编码 / 路径 | GBK 与 UTF-8 文件各一份；`"C:\temp\中文 目录\x.txt"` | 不乱码、不失败 | 乱码落盘 / not found |
| 数值 | `0`、`-1`、`2147483648`、除零 | 明确校验 | 除零崩溃 / 负数静默截断 |
- **判定**：每类写一行 `输入 → 实际输出`；未测的写 `未测: <原因>`，**禁止留空**。
- **数字上限**：至少覆盖 4/6 类，或书面说明本改动只涉及哪 k 类。
- **回执**：`EDGE k/6: <已测项>`。
- **红线**：边界探针只在副本 / 测试数据上跑（不违背 `SKILL.md:131` R5 红线）。
### 3.4 长任务降标 DRIFT（D6）
- **触发**：任务 ≥5 步，或时长 >30 分钟（与 R13 并用）。
- **动作**：把每步 `(回执, 证据行数)` 排两列；某步证据行数 = 0，或比前一步低 >50% → 打
  `DRIFT at step k: 证据 <a>→<b> → 回到该步补证据`。
- **数字上限**：连续 2 步零证据 → 触发 R4 熔断；不允许"后面几步省略细节"。
- **为何用"证据密度"**：R6 已管调用次数、R13 已管 CHECKPOINT 频率；证据密度是第三维度，不重复。
### 3.5 替身对照表（D4）
| 用户说 | 不算（替身） | 最低真实证据 |
|---|---|---|
| "跑起来看看" | 只跑单测 | 真实进程启动日志 + 一次真实请求/交互输出 |
| "验证接口" | 只 curl `/health` | 用户要的那个端点返回的真实字段与值 |
| "打包后能用" | 只跑 dev server | 安装/解包后真实可执行入口的输出 |
| "数据能导入" | 只跑 mock fixture | 真实样本（或副本）导入后的行数/校验和 |
| "已修复" | 只改代码不重跑 | 修复前失败、修复后成功的**同一命令**两组输出 |
- **判定**：证据里命令指向的入口必须等于用户指定入口；不等 → `UNVERIFIED: <入口> + 复现步骤`。
- **数字上限**：`UNVERIFIED` 项 ≤ 总项数 1/3；超限必须走 R13 `HANDOFF`，不许标完成。
### 3.6 提问式收尾自检（D7，**仅按需**）
- **判定式**：回复最后 3 行匹配 `吗？|要不要|是否要|需要我|要我继续|你希望` → 逐个核对是否属于

## 4. 反例：哪些措辞反而鼓励偷懒
### 4.1 规则侧的措辞反例（按 `CONTRIBUTING.md:7` 第一条直接判不收）
| 反例 | 为什么坏 |
|---|---|
| "尽量保证交付完整" / "建议完整实现" | 无触发、无数字 = 口号；"尽量"给了不做完的台阶 |
| "在时间允许时处理边界情况" | 时间永远不允许；等价于不做 |
| "如有必要补测试" / "可以考虑处理错误分支" | "如有必要/可以考虑"是**不做**的合法化措辞 |
| "N 项要求尽量都做" | N 未定义 → agent 自己缩小 N（D2 的根源） |
| "除非万不得已不要留 TODO" | 例外可被无限引用；数字必须是硬 0 命中 |
| "交付要完整、不要偷懒" | 纯态度词，删掉 agent 行为不变（违反 `CONTRIBUTING.md:9`） |
### 4.2 任务/提示侧的措辞反例
`尽量` / `如果可以` / `最好` / `有空的话` / `酌情` / `适当完善` / `能补就补` / `核心功能先做出来` /
`细节无所谓` / `你自己看着办` / `先这样我看看` / `剩下的我来` / `大概率没问题就行`。
→ 这些把"是否完成"从**约束**降级为**愿望**。替换写法：
| 反例 | 替换 |
|---|---|
| "尽量都实现" | "逐条实现；未做的列出来并说明原因" |
| "尽量跑一下" | "跑一次真实入口，贴命令与原样输出" |
| "有问题再说" | "能做到什么程度写清楚；做不到的标 `UNVERIFIED` + 复现步骤" |
| "先这样我看看" | "以 `DONE m/N` + 证据交付，未验证项显式标注" |
