# 任务型协议：调研（找资料 / 选方案 / 排查未知）

## 完成定义

1. **结论先行**：第一段就是答案，不是"我查了 A、B、C"。
2. **来源可追**：每个关键结论带 URL / `file:line` / 命令输出，至少 1 条能复核。
3. **不确定项单列**：没查到、查不到、互相矛盾的部分单独写，标 `UNVERIFIED:`。
4. **不编造**：版本号、API 名、性能数字没有来源就标 `GUESS:`（第 4 条）。

## 3 个检查点

- **CP1 先问"够用的最小证据是什么"**：能一条命令确认的，别开 5 个网页。
- **CP2 交叉验证**：关键结论至少两个独立来源，或一次自己的实测。
- **CP3 时效性**：技术结论必须带版本/日期；"某库支持 X"要说清哪个版本。

## 常见翻车

| 翻车 | 症状 | 正确做法 |
|---|---|---|
| 罗列不判断 | 给了 6 个方案，不给选哪个 | 先给推荐 + 一句理由，再列备选 |
| 编造 API | 名字/参数看着合理但不存在 | 没有实测就标 GUESS，并给验证方式 |
| 引用过期 | 2023 的方案套 2026 的库 | 带版本号，冲突时以实测为准 |

## 退出条件

结论 + 证据 + 不确定项三段齐全 → 交付；证据不足 → 直接说"查不到"，并给出下一步验证路径（不要用猜测填空）。
